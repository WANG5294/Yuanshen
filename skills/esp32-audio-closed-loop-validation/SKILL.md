# 音频闭环验证

静态代码和主机预览只能验证算法；实机链路还包含 Q3、蜂鸣器/喇叭、采样时钟、RMT
块接缝、GC 与环境声。音频需求只有经过有效实录才能宣称实机合格。硬件接法和波形生成
分别见 `esp32-led-key-buzzer` 与 `esp32-dac-pwm-rmt-and-neopixel`。

## 前置检查

- VirtualBox 环境先确认宿主机为虚拟机启用“音频输入”；否则可能录到全零。
- 每次闭环先调用 `mic_check`，确认非全零并记录噪声底 RMS；既往实测约 0.03 仅为
  历史参考，不能替代本次测量。
- 麦克风放在发声体数厘米内，固定距离和增益；防止自动增益、风噪和桌面振动污染比较。
- 先确认要验收的输出是板载压电蜂鸣器还是外接功放/喇叭；两者响度行为不同。

## 可重复触发

agent 无法按物理 KEY。将播放逻辑封装为可导入函数，例如 `piano.play()`，让录音工具
先启动采集，再延迟约 0.5s 经 REPL 调用：

```text
play_and_record("import piano; piano.play()", "rec.wav", 4)
```

这只替代“按键动作”，不替代对按键电路本身的测试。触发函数应能返回，避免死循环占住
REPL；连接失败按调试恢复 Skill 处理。

## 标准流程

1. `mic_check`：记录噪声底、峰值和通道有效性。
2. 对算法生成的 preview WAV 调用 `analyze_wav`，确认参考音高/包络本身正确。
3. `play_and_record` 软件触发实机并录制，时长覆盖前后静音。
4. 对实录调用 `analyze_wav`，提取峰值、RMS、基频、瞬态和包络。
5. `compare_audio rec.wav preview.wav`；比较前做时间对齐，必要时只裁剪有效段。
6. 按任务指标判定，失败就修改输出实现并重复完整闭环。

工具参数以当前 MCP schema 为准，不从示例猜测。

## 扫频、警笛与变频音

不要用单一 `expect_f0` 或整段单一 FFT 验收扫频。对 400→480→400Hz 一类轨迹：

1. 用短时频谱（建议 50~100ms 窗）提取每窗目标频带主峰，形成实测频率轨迹。
2. 把轨迹与 `f(t)` 对齐，分别报告上升段、峰值、下降段和时间误差。
3. 对响度轨迹使用同窗 RMS，扣除同配置静音基线后再与目标包络比较。
4. 同时录一份固定频率、固定占空比的阳性对照。阳性对照可检出而扫频不可检出时，
   优先检查扫频实现、触发状态和分析方法，不要断言麦克风或蜂鸣器存在物理限制。

生成扫频 preview 时必须累计相位：

```text
phase[n+1] = phase[n] + f[n] / sample_rate
sample[n] = waveform(frac(phase[n]))
```

禁止使用 `phase = t * f(t)`；当频率随时间变化时，其导数会变成
`f(t) + t*f'(t)`，生成的实际瞬时频率与目标轨迹不一致。

`analyze_wav` 当前适合近似稳态音，不足以单独判定扫频。它返回的全局主峰可能是
50/60Hz 环境噪声、谐波或固定中段的局部峰值。扫频验收必须补充时频轨迹或分窗目标频带
能量，不能把“全局 f0 不等于中点频率”直接判为固件失败。

## 匹配基线与录音增益

- 静音基线和发声录音必须在相同设备、Capture 增益、距离、时长和采样格式下连续完成。
  改过增益后，旧 `mic_check` 数字和旧基线全部失效。
- 记录并检查削波样本比例。peak=1.0 且大量样本满幅时，先降低增益；削波录音中的
  全局 RMS、峰值比和基频均不可靠。
- 不用不同时间采集的 `signal_peak / noise_rms` 单独归因声音。至少同时报告发声窗相对
  同录音前/后静音窗的变化，以及目标频带相对匹配基线的功率增益。
- 调整 ALSA/PulseAudio Capture 属于全局环境变更。操作前保存原值，测试结束后恢复；
  每个新增益最多做一组基线和发声 A/B，禁止在无新假设时反复试探。

## 触发与归因

- `repl_exec` 或 `play_and_record` 返回 `OK` 只证明代码调用返回，不证明 PWM 曾为非零，
  更不证明麦克风收到声音。
- 在触发函数中输出可审计的开始、关键参数和结束标记；必要时另外运行固定 440Hz、
  50% duty、3s 的阳性对照。
- 只有发声窗出现与目标频率/轨迹一致、相对匹配基线显著提高且随停止而下降的频带能量，
  才能归因于蜂鸣器。
- 阳性对照已有明确目标频带增益时，不得再以“VirtualBox 麦克风无法捕获板载蜂鸣器”
  作为失败根因。应把结论限定为当前动态程序、当前录音或当前分析尚未通过。

## 有效性与合格判据

### 录音有效

实录信号峰值至少达到本次噪声底 RMS 的 5 倍，否则闭环无效，不能宣布合格。先移动麦克风、
排除静音/接线，再在硬件安全范围内增大输出；仍不满足就报告“实机验证失败”及数字。
更稳健时同时报告有效段 RMS 与噪声 RMS 的 dB 比：

`SNR_dB = 20 * log10(signal_rms / noise_rms)`

峰值比不是严格 SNR，汇报时不要混称。

### 音高

报告目标频率、估计基频与音分偏差：

`cents = 1200 * log2(f_measured / f_target)`

绝对偏差超过 10 cents 时检查 RMT `clock_div`、ticks、实际采样率、FFT 窗长和录音设备
采样率。谐波很强的压电蜂鸣器可能导致基频检测倍频/半频，应结合频谱人工核对。

### 包络与响度

响度/包络任务必须有 preview，并报告时间对齐后的包络相关系数；目标为 `>=0.8`。
用约 20~25ms 窗计算 RMS 包络，相邻窗平均相对起伏目标 `<10%`（预期音符边界和设计
瞬态应从稳态统计中排除）。相关高不代表绝对响度相同，还要报告增益差和有效信噪。

### 爆音与哒声

| 现象 | 优先判断 |
|---|---|
| 实录有规律尖峰、preview 无 | RMT/缓冲块接缝；测间隔是否约 `CHUNK/RATE` |
| 首尾孤立尖峰 | 直流/波形阶跃；加约 5~10ms 斜坡 |
| 包络低相关且信噪低 | 环境噪声或麦克风太远，重录 |
| 音高稳定但音色不同 | 发声体与麦克风通道染色；不要用谐波逐点一致作为硬指标 |

基频和周期性尖峰通常较可信；包络在固定增益/距离下中等可信；谐波与音色受通道染色
显著，只比较趋势。

## 结果记录

最终汇报至少包含：固件/代码版本、输出路径、录音文件、噪声 RMS、实录 peak/RMS、
峰值噪声比或 SNR、目标/实测频率与 cents、包络相关（若适用）、尖峰周期和明确
pass/fail。扫频任务还要包含频率轨迹误差、目标频带 A/B 增益、削波比例和阳性对照结果。
不得用“确认发声”“听起来正常”替代数字，也不得用静态检查替代失败的实录。
