# Yuanshen v1.0 正式版架构

## 1. 设计目标

Yuanshen v1.0 正式版将既有 v4 系列能力冻结为首个正式发布基线，并重点保证：

1. 固定内容尽可能形成稳定的 Prompt Cache 前缀。
2. 用户、模型和工具产生的历史只追加，不静默改写。
3. 当前 TodoList 永远位于本轮输入末尾。
4. 每轮模型调用都有可复现、可审计的完整 Markdown 快照。

## 2. 主流程

```text
启动
  → 加载 API Key、Skill、wiring.md 与 MCP 工具
  → 用户输入任务
  → 独立前置模型读取硬件参考手册、wiring.md 和用户要求
  → 生成规范化任务要求与接线
  → 用户确认
  → 创建 file/<任务>/
  → 保存 requirement.md，原子更新 wiring.md
  → 冻结 System Prompt 与工具定义
  → Agent 循环
      → 调用模型
      → 执行工具
      → 追加 assistant/tool_result 历史
      → 把最新 TodoList 放在最新 User 内容末尾
      → 输出用户可见状态
      → 写 rounds/round-NNNN.md
  → 输出最终报告
  → 写完整 userprompt.md
```

## 3. 固定 System Prompt

System Prompt 在单个任务开始时构建一次，循环内不重新读取或改写。它完整承担：

- Agent 身份、职责和 ESP32 工作范围；
- 指令优先级与三段式输入契约；
- 主线任务及完成条件；
- Skill 发现和加载规则；
- 本地工具、MCP 工具及调用接线；
- 用户确认后的 `requirement.md` 任务要求快照；
- 用户确认后的 `wiring.md` 接线快照；
- 当前任务目录；
- 文件、安全、串口和 GPIO 边界；
- 实机验证红线；
- 最大循环次数；
- 屏幕状态与逐轮审计规则。

Skill 名称与描述、工具 schema、接线快照和任务目录在不同任务之间可以变化，但在同一任务中冻结。

ESP32 板级硬件参考手册只进入独立的前置规范化调用，不进入主体 Agent 的 System
Prompt 或循环历史。主体 Agent 只使用用户确认后的 `requirement.md` 内容、
`wiring.md` 快照和按需加载的硬件 Skill。

## 4. 追加式消息历史

历史完整保留：

- 用户确认后的规范化需求；
- 每轮 User 内容；
- 每轮 assistant 文本；
- assistant 工具调用名称、ID 和参数；
- 完整 `tool_result`；
- Skill 工具返回的完整正文；
- 最终模型回复。

已发送的消息不回写、不摘要。新内容只追加到历史尾部。

## 5. TodoList

TodoList 由程序维护，必须且只能包含以下四项；不可改名、调序、删除或插入子项：

1. 编写代码
2. 烧录代码
3. 测试代码
4. 完成

当前 TodoList 是最新 User 内容的最后一段，后面不允许追加其他文本。旧 TodoList 作为历史快照保留；最新末尾版本是当前唯一权威状态。

## 6. 用户可见循环状态

每轮工具开始时立即输出“执行中”，工具结束后在终端同一行改写为成功或失败：

```text
第 3 轮｜第 18 秒｜工具：upload（MCP）｜目的和作用：把程序上传为板上 main.py，建立可启动的烧录证据。 …… 成功
```

失败示例：

```text
第 4 轮｜第 26 秒｜工具：repl_exec（MCP）｜目的和作用：执行板上 main.py 并读取串口结果，验证烧录后的程序。 …… 失败
```

规则：

- 秒数从用户确认规范化需求和接线后以 0 秒开始累计；需求规范化和等待确认不计时；
- 持续时间使用单调时钟计算，不受系统校时影响；
- 状态行末尾必须是“成功”或“失败”；
- Skill 显示技能名，不在屏幕复述正文；
- 目的和作用约 30–50 个汉字，超长时由程序截断；
- 不调用工具的最终轮显示“调用工具：无”。

## 7. 文件结构

```text
file/<时间戳_任务摘要>/
├── rounds/
│   ├── round-0001.md
│   ├── round-0002.md
│   └── ...
├── userprompt.md
├── requirement.md
├── main.py
└── 其他任务产物
```

每个 `round-NNNN.md` 是创建后不回写的轮次快照，完整包含：

- 元数据；
- System Prompt；
- 工具定义；
- 截止该轮的完整 User/Assistant/Tool 历史；
- 本轮模型原始响应；
- 本轮结束时的 TodoList。

`files/` 是 v3 历史任务目录。v4 不迁移、不覆盖、不删除其中的数据。

## 8. Skill 与 MCP

Skill 使用渐进加载：

- System Prompt 固定保存 Skill 的名称和描述；
- 任务匹配时通过 `Skill` 工具读取正文；
- Skill 正文作为工具结果进入追加式历史；
- 后续轮次继续携带该工具结果。

MCP 采用 stdio JSON-RPC。工具定义在任务开始时冻结，避免循环内 schema 顺序或文本变化破坏公共前缀。ESP32 设备通道使用持久 Raw REPL：单一 USB 串口可自动选择，多设备时要求明确指定。上传先写临时文件并在设备端核对大小和 SHA-256，再以备份/替换方式提交；设备 traceback 或协议帧不完整会作为失败返回。主程序退出时终止 MCP 子进程并释放串口。
